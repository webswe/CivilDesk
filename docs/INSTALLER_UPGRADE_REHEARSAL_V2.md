# CivilDesk 0.1.1 corrected installer upgrade rehearsal

This local workflow is inert until the owner separately authorizes a normal push of its exact reviewed commit to `verification/installer-upgrade-rehearsal-0.1.1-v2`. A later push to that branch or a rerun must not execute the installer job: the job requires the initial branch-creation event and run attempt 1. Do not manually rerun or replace the branch if the run fails.

The disposable GitHub-hosted `windows-2022` runner builds immutable sources `7d293bbc61dce674d796220e3241571a9f15aa6b` (historical 0.1.0) and `5d46e131093bc59205680ad19167319f9acfb71e` (corrected 0.1.1). Source fetches disable credentials and verify both full commit IDs. The workflow commit must be a single direct child of the corrected candidate and change only the eight listed rehearsal files. No installer or diagnostic artifact is uploaded.

The historical 0.1.0 installer is **known to contain** `brightspace-synthetic.exe`. Its archive and installed directory must contain exactly that one fixture at the expected path and no other unexpected executable or private file. This exception applies only to 0.1.0. It does not mean the old installer is clean. The 0.1.1 archive must pass the ordinary release-bundle guard and the upgraded installation must contain no fixture. The harness never deletes the legacy executable to manufacture a pass.

The rehearsal installs 0.1.0 into the disposable current-user profile, launches the actual production-identity app, seeds synthetic tasks, projects, challenge progress, calendar, portfolio, settings and an external file, and checks schema v10, SQLite integrity, foreign keys and record identities. It creates two independently checked SQLite backups after closing the app. It installs 0.1.1 over 0.1.0, verifies installed identity, version and file inventory, relaunches and compares application-level and database records, restarts again, uninstalls and verifies data retention. Finally it reinstalls historical 0.1.0, explicitly expects its fixture to return, restores the independent backup, verifies recovered records and uninstalls. Application rollback and database restoration are separate checks.

Generated NSIS script inspection shows an in-place installation copies the current main executable but has no general deletion of obsolete files. Therefore the legacy fixture may survive the upgrade. A failure at that assertion is evidence of an upgrade-cleanup defect and requires a separate product decision; it must not be handled by deleting the file in the test harness.

This rehearsal does not verify running-app upgrades, cancellation, interrupted installs, permission-denied recovery, installation without a pre-existing WebView2 runtime, publisher reputation, or delivered-artifact privacy. The installers are unsigned unless Authenticode evidence says otherwise. Do not distribute them on the basis of this workflow alone.
