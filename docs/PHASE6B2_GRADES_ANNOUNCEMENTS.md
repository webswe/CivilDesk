# Phase 6B.2 — Grades and Announcements (synthetic only)

## Verified D2L-CLI contract

Inspected D2L-CLI at `17cf68351468dd04db1b1cb005b146a0c5deb181`, including its machine-interface documentation, models, and command tests. The fixed commands are `d2l grades list --course <ASCII decimal ID> --json --include-completeness` and `d2l announcements list --course <ASCII decimal ID> --json --include-completeness`. Both use a required course ID. A successful response has one JSON object and `"completeness":"unknown"`; there is no verified total, page limit, pagination cursor, or end marker. Provider order is preserved without a chronological or full-history claim. Nonzero exit or malformed output is a failed course read, not an empty list.

Grades return `grade_items` with exactly `course_id`, `label`, nullable `displayed_points`, nullable `displayed_grade`, nullable `displayed_weight`, and `feedback_availability` (`none`, `present`, or `unknown`). There is **no stable grade-item ID**, category, grade status, feedback text, reliable numeric score, or verified course average. The three displayed values remain source strings. Null means the cell was blank, not zero or confirmed ungraded. A literal `0` remains visible as `0`. Duplicate titles are allowed. CivilDesk uses only snapshot row order for React presentation keys; those keys are ephemeral and have no cross-refresh identity. It does not calculate grades, infer pass/fail, or display an invented course average.

Announcements return `announcements` with exactly `course_id`, numeric `announcement_id`, `title`, nullable sanitized plain-text `body`, and a validated relative `detail_reference`. The verified ID is unique within the course listing and is keyed with portal and course provenance. The relative reference is retained only as parsed data; CivilDesk does not make it an external link or fetch it. There are no publication dates, authors, urgency, pinned state, read state, or verified ordering timestamps. The JSON body is complete for each returned row, while the list itself has unknown completeness. React renders title and body as text nodes; markup-like text stays inert, and external URLs are not linked or loaded.

## Architecture and behavior

Grades and Announcements are tabs inside the existing synthetic Class detail. The Overview remains, and Assignments opens the existing Assignment Calendar. The two new reads occur only after an explicit refresh. A fixed Rust command with no frontend arguments first obtains the restricted synthetic course catalog, then checks at most 12 listed IDs. It reports skipped courses and individual read failures. Each child retains the canonical adjacent synthetic executable check, SHA-256 fingerprint, fixed profile and portal, cleared environment, bounded output, five-second timeout, cancellation, Windows Job Object cleanup, and sanitized errors. Production, Acceptance, and ordinary Dev builds cannot launch academic reads; debug Dev and browser preview return hard-coded fictional samples. No real account, credential store, or owner's D2L-CLI executable is used by the synthetic tests.

The two snapshots are kept only in React memory. A global refresh failure leaves the previous snapshot visible and marks it stale. If one course fails in a later read, its prior successful rows remain visible with a per-course stale warning; other courses use the new result. An empty successful page is labeled as an empty *available page*, never a complete gradebook or history. Offline mode disables refresh and retains available in-memory data. Restart clears these snapshots. No import, automatic synchronization, grade editing, read tracking, School table mutation, or schema migration was added; SQLite remains v10.

## Verification and limits

Synthetic fixtures cover duplicate grade and announcement titles, blank score versus displayed zero, nonnumeric grade strings, missing feedback and body, long text, HTML-like text, external URL text, empty and partial pages, per-course failure, malformed JSON and records, oversized output, timeout, and cancellation through the existing process boundary. The strict Rust parser rejects extra fields, mismatched course association, invalid announcement references, unsupported completeness claims, and malformed feedback states. Native E2E drives the isolated `com.webswe.civildesk.e2e` binary and checks the database after every specification.

Remaining limits: no verified grade-item identity or feedback content; no evidence for grade status, grading category, average, announcement publication metadata, or complete history; a 12-course read cap; in-memory snapshots only; and the previously documented same-user executable replacement race. Real Brightspace retrieval needs a separate owner authorization and live-contract review.

Final local verification: TypeScript, ESLint, production frontend build, and Brightspace and Notion isolation guards passed; 308 frontend tests, 143 Rust library tests, and 27 E2E harness tests passed. Rust formatting and Clippy passed. The full native WebView2 run passed 114 tests across 14 specifications, including 21 Brightspace and 16 Notion tests. Each isolated database remained schema v10, passed SQLite integrity, and had zero foreign-key violations. Wide and narrow native screenshots were inspected for the class overview, grade rows, announcement bodies, empty and error states, duplicate titles, displayed zero, and long content. Direct development-window inspection was not performed; the actual native E2E WebView2 interface was available for visual review.
