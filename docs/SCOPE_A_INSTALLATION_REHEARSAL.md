# Disposable Scope A installation rehearsal

This repository holds a **fail-closed, locally reviewable** rehearsal. No protected installer has been installed by this change. `APPROVED_FROZEN` remains `None`. The workflow has no push trigger. GitHub requires `workflow_dispatch` workflows to exist on the default branch, so this development-branch copy cannot run by a verification-branch push.

## Owner-managed controls required before any privileged run

1. Review and separately approve a commit that places the workflow on protected `main`. Apply an owner-controlled ruleset to **all branches** so `.github/workflows/protected-installation-rehearsal.yml` and its called scripts cannot be changed or dispatched from an unreviewed branch. GitHub manual dispatch can select a branch ref; the source-level `main` check cannot defend against a modified branch copy that removes its own gate. The workflow must be dispatched with `main` as its workflow ref and a separately reviewed full lowercase `source_sha` input. The checkout uses that SHA, never a moving branch name.
2. Configure the GitHub environment `scope-a-installation-rehearsal` with required owner reviewers, restrict deployments to `main`, and disable administrator bypass. Confirm these protection features are available for this repository plan and visibility. A reviewer must inspect the exact input commit before approving the job. If the initiator is also the sole owner reviewer, plan an independent reviewer before enabling “prevent self-review”; do not silently substitute a weaker approval.
3. Set **only an environment-scoped** variable `CIVILDESK_SCOPE_A_REHEARSAL_APPROVED_SHA` to the approved full source SHA. Ensure no repository or organization variable of the same name exists. Missing, malformed, or mismatched values stop the first step. The owner must clear or rotate the value after one attempt; a rerun requires fresh review and approval.
4. Confirm the repository cannot route this job to self-hosted runners, including custom labels matching `windows-2025`. The workflow checks `RUNNER_ENVIRONMENT=github-hosted`, `RUNNER_OS=Windows`, and `RUNNER_ARCH=X64` before checkout, but runner-provided environment variables alone are not an unspoofable machine identity. If runner policy cannot establish this, do not run the workflow.
5. Confirm exact source ancestry, a clean destination, green ordinary and protected build CI for the approved SHA, and that no other branches or workflows are being changed. A verification-branch push alone does not authorize installation. No GitHub environment or repository setting is changed by this commit.

The job references the environment before it receives a runner. Its first inline PowerShell step checks the event, `main` workflow ref, workflow SHA, runner classification and architecture, dispatch input, and independently managed approved SHA. It executes before checkout or external actions. Checkout uses the exact input SHA with credentials persistence disabled. A provenance script checks HEAD, tracked content, untracked source, and critical source and lockfile Git blobs before dependencies, after `npm ci --ignore-scripts`, and after the Tauri build. `node_modules`, `dist`, and `src-tauri/target` are expected ignored build outputs. Lockfile integrity constrains npm downloads; it does not make third-party dependencies intrinsically trustworthy. `npm ci --ignore-scripts` prevents npm lifecycle scripts during installation. Tauri's build still executes reviewed dependencies and the project's `beforeBuildCommand`.

The three external actions are pinned to independently inspected full commits: `actions/checkout` `11d5960a326750d5838078e36cf38b85af677262` (checkout), `actions/setup-node` `49933ea5288caeca8642d1e84afbd3f7d6820020` (Node 24), and `actions/setup-python` `a26af69be951a213d495a4c3e4e4022e16d87065` (Python 3.11). The Rust setup and cache actions were removed. The runner's preinstalled Rust compiler is checked for the x64 MSVC target and its version is logged; compare that changing image input with the reviewed build baseline.

## Evidence and limits

The runner records source SHA, runner image/version, Tauri CLI version, generated NSIS digest, pre-install installer SHA-256, Authenticode status, installation paths, registry results, standard-token SID/group/elevation/privilege results, ACL checks, firewall findings, and synthetic SQLite findings. JSON is written under `RUNNER_TEMP` and printed to the job log; no diagnostic artifact or installer is uploaded. Gate failures stop further acceptance work, and cleanup failures are recorded separately without replacing the primary failure. A partial install that lacks a safe recorded uninstaller is reported as a failed cleanup and left to disposable VM destruction.

The separate local account has a generated 15-character name. The harness records the created SID, checks it again before removal, and never deletes an existing or mismatched account. The probe checks its actual token SID against both the created account and parent runner SID, administrator group, elevation, and dangerous privileges. It resolves the loaded profile from the token SID and resets inherited profile environment variables before launching CivilDesk. Negative filesystem checks only count specific access-denied errors; missing targets and unrelated I/O failures are failures.

The synthetic package is a copy of the runner's PowerShell executable under a rehearsal-only Program Files root, with a synthetic independent manifest. It is not the actual `3ce1648` package and has no compiled trust approval. Synthetic HKCU registration and shortcut coexistence tests detect duplicate installation scopes but do not prove a real HKCU-to-HKLM upgrade. A generated v8 SQLite file tests backup, v10 migration, integrity, foreign keys, failed migration, and matched v8 restoration. No owner database, Credential Manager entry, Brightspace endpoint, or real frozen D2L-CLI is accessed.

The checked-in workflow supplies no controlled non-loopback endpoint. Firewall rule selection and removal can pass, while outbound enforcement remains **NOT VERIFIED**. Realistic UAC prompts, application-binary rollback, a real current-user installer transition, and Windows publisher authenticity also remain **NOT VERIFIED**. GitHub-hosted Windows runners disable UAC. These gaps cannot be promoted to PASS by the first rehearsal.
